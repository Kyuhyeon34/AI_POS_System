# 🥐 BreadVision — AI 빵 인식 POS

카메라로 트레이 위의 빵을 찍으면 **AI가 빵 종류와 개수를 알아서 계산대에 담아 주는** POS입니다.

```
 ┌──────────── 젯슨 (매대 아래) ───────────┐          ┌──────────── PC (계산대) ────────────┐
 │  USB 카메라 ─▶ 카메라 영상 서버 (8090) ─┼──영상──▶ │  POS 프로그램  (run_pc.bat)          │
 │               AI 추론 서버     (8092) ◀┼──사진──  │   · 실시간 화면 · 주문 · 결제         │
 │               (TensorRT, 모델 2개 앙상블)│──결과──▶ │   · 데이터 수집 · 모델 학습 버튼      │
 │  턴테이블(선택) ◀── USB                  │          │  라벨링 프로그램 (run_autolabel.bat) │
 └─────────────────────────────────────────┘          └─────────────────────────────────────┘
                     같은 공유기(인터넷)에 연결되어 있어야 합니다
```

- **젯슨**: 카메라와 AI 계산만 합니다. 처음 한 번 설치하면 **전원만 켜도 자동으로 켜집니다.**
- **PC**: 화면을 보고 누르는 모든 것(POS, 데이터 수집, 학습 버튼, 라벨링)을 합니다. **젯슨 주소는 자동으로 찾습니다.**

## 2. 젯슨 설치 (처음 한 번)

### 2-1. 카메라 꽂기
USB 카메라를 젯슨에 꽂습니다. (턴테이블이 있으면 그것도 USB로 꽂습니다)

### 2-2. 코드 받기
젯슨 터미널에서 한 줄씩 붙여넣고 `Enter` 를 누릅니다.

```bash
cd ~
git clone <저장소 주소> breadvision
cd breadvision
```

- `<저장소 주소>` 는 GitHub 저장소 페이지의 초록색 **Code** 버튼을 누르면 나오는 주소입니다.
  예: `https://github.com/계정이름/breadvision.git`
- **비공개(private) 저장소**라면 아이디와 비밀번호를 물어봅니다.
  비밀번호 칸에는 GitHub 비밀번호가 아니라 **토큰**을 넣어야 합니다.
  (GitHub → 오른쪽 위 프로필 → Settings → Developer settings → Personal access tokens → Generate new token → `repo` 체크)

### 2-3. 설치 스크립트 실행

```bash
./jetson/install.sh
```

알아서 아래 순서로 진행합니다. **전체 15~25분** 걸립니다.

| 단계 | 하는 일 | 시간 |
|---|---|---|
| 1/6 | JetPack(TensorRT·OpenCV) 확인 | 몇 초 |
| 2/6 | 필요한 파이썬 패키지 설치 (**비밀번호를 물으면 젯슨 비밀번호 입력**) | 1~3분 |
| 3/6 | 카메라·턴테이블 사용 권한 | 몇 초 |
| 4/6 | 기본 설정 파일 만들기 (빵 12종 목록 등) | 몇 초 |
| 5/6 | **AI 엔진 준비** — 저장소에 든 엔진(m13_A·m13_B)이 있으면 그대로 쓰고, 없는 것만 이 젯슨 전용으로 변환 — 화면이 멈춘 것 같아도 기다리세요 | 몇 초~20분 |
| 6/6 | 전원을 켜면 자동으로 시작하도록 등록 | 몇 초 |

> ⚠️ 저장소의 엔진은 **Jetson Orin Nano Super · JetPack 6.2 · TensorRT 10.3** 에서 만든 것입니다.
> 다른 기종이나 JetPack 버전이면 AI 추론 서버가 켜지지 않으니 `./jetson/build_engines.sh --force` 로 다시 만드세요 (10~20분).

### 2-4. 잘 켜졌는지 확인
설치가 끝나면 이런 화면이 나옵니다.

```
================ BreadVision 상태 ================
젯슨 IP 주소 : 192.168.0.23
카메라 영상  : ✅ 켜짐   (브라우저에서 http://192.168.0.23:8090/stream)
AI 추론 서버 : ✅ 켜짐   (포트 8092)
  모델       : m13_A.engine + m13_B.engine  (앙상블)
  클래스     : 12 종
자동 시작    : ✅ 부팅하면 자동으로 켜짐
==================================================
```

- ✅ 가 모두 보이면 **젯슨은 끝입니다.** 이제부터는 전원만 켜면 됩니다.
- **젯슨 IP 주소**는 적어 두세요. PC가 자동으로 찾지만, 못 찾을 때 필요합니다.
- 카메라 영상이 ❌ 이면 [10번 문제 해결](#카메라-영상이--꺼짐으로-나와요) 을 보세요.
- ⚠️ 3/6 단계에서 "그룹에 추가했습니다" 가 나왔다면 **젯슨을 한 번 재부팅**하세요: `sudo reboot`

## 3. PC 설치 (처음 한 번)

### 3-1. 파이썬 3.11 설치
1. https://www.python.org/downloads/release/python-3119/ 에 들어갑니다.
2. 맨 아래 **Windows installer (64-bit)** 를 받아 실행합니다.
3. ⚠️ 첫 화면 아래의 **「Add python.exe to PATH」 를 꼭 체크**하고 **Install Now** 를 누릅니다.

### 3-2. 코드 받기 (둘 중 하나)

**방법 A — ZIP 으로 받기 (쉬움)**
1. GitHub 저장소 페이지에서 초록색 **Code → Download ZIP** 을 누릅니다.
2. 받은 ZIP 을 오른쪽 클릭 → **압축 풀기** → 원하는 곳(예: `바탕화면\breadvision`)에 풉니다.

**방법 B — git 으로 받기** (PowerShell)
```powershell
cd $HOME\Desktop
git clone <저장소 주소> breadvision
```

### 3-3. POS 켜기
1. 받은 폴더를 엽니다. (`run_pc.bat` 파일이 보이는 폴더)
2. **`run_pc.bat` 을 더블클릭**합니다.
3. 처음 한 번은 필요한 프로그램을 받느라 **2~5분** 걸립니다. 검은 창을 닫지 마세요.
4. 검은 창에 `[젯슨 연결] 192.168.0.23 — 추론 8092, 카메라 8090` 처럼 나오고 POS 화면이 뜨면 성공입니다.

> 💡 파란 경고창 **"Windows의 PC 보호"** 가 뜨면 **추가 정보 → 실행** 을 누르세요.

**PowerShell 에서 직접 켜고 싶을 때** (폴더에서 `Shift + 오른쪽 클릭 → 여기에 PowerShell 창 열기`)
```powershell
py -3.11 -m pip install -r requirements-pc.txt     # 처음 한 번
py -3.11 main.py
```

젯슨 주소를 직접 지정해서 켜기 (자동으로 못 찾을 때):
```powershell
$env:BREADVISION_INFER_URL="http://192.168.0.23:8092"
$env:BREADVISION_CAMERA="http://192.168.0.23:8090/stream"
py -3.11 main.py
```
(`192.168.0.23` 은 [2-4](#2-4-잘-켜졌는지-확인) 에서 적어 둔 젯슨 IP 로 바꾸세요. 이 방법은 **같은 PowerShell 창에서** 켤 때만 적용됩니다)

## 4. POS 사용하기

1. **POS 탭** → 아래쪽 카메라 목록에서 **「📷 젯슨 카메라 (8090)」** 가 골라져 있는지 확인 → **카메라 시작**
2. 트레이를 카메라 아래에 놓으면 실시간으로 초록 박스가 보입니다.
   - 🟢 초록 = 확실함 (55% 이상) · 🟡 노랑 = 자신 없음
3. **상품 인식 실행** 을 누르면 인식된 빵이 오른쪽 주문표에 담깁니다.
4. 수량 조정 → **결제 처리**

처음에는 가격이 모두 0원입니다. **「상품 관리」 탭**에서 가격을 넣어 주세요.

### 회원 적립 (QR)
1. **회원 QR 스캔** 을 누르면 빵 인식이 멈추고 **QR 만** 찾습니다.
2. 손님 휴대폰의 BreadVision 앱 QR 을 카메라에 대면 **자동으로 회원이 등록**됩니다. (버튼을 다시 누를 필요 없음)
3. **휴대폰을 치우고 2초** 지나면 빵 인식으로 돌아갑니다.
   휴대폰이 보이는 동안 빵 인식을 멈춰 두는 것은 앱 화면(주황 버튼)을 빵(로투스)으로 착각하지 않게 하기 위해서입니다.
4. 포인트(결제 금액의 3%)는 **결제 처리** 때 적립됩니다.

- 스캔 중에 버튼을 다시 누르면 취소, 30초 동안 QR 이 안 보이면 저절로 끝납니다.
- 회원 QR 이 아니거나 등록되지 않은 회원이면 안내만 뜨고 계속 스캔합니다.

### 카메라 고르기
POS 탭 카메라 화면 아래의 목록에서 고릅니다. 고르면 바로 바뀌고 다음에도 기억합니다.

| 항목 | 뜻 |
|---|---|
| 📷 젯슨 카메라 (8090) | 젯슨에 꽂힌 카메라 (**보통 이것**) |
| 💻 PC 카메라 0 (보통 내장) | 노트북 내장 카메라 |
| 💻 PC 카메라 1, 2 | PC에 직접 꽂은 USB 카메라 |
| ✏️ 번호/주소 직접 입력… | 번호나 `http://…/stream` 주소를 직접 입력 |

**카메라 찾기** 버튼을 누르면 이 PC에 연결된 카메라 번호를 찾아 줍니다.

## 5. 새 빵 사진 찍기 (데이터 수집)

**「데이터 수집」 탭**에서 합니다.

1. **수집할 상품** 을 고릅니다. (없으면 「상품 관리」 탭에서 먼저 추가)
2. **수집 방식** 을 고릅니다.
   | 방식 | 언제 |
   |---|---|
   | **한 개 — 빵 1개 자동 인식** (기본) | 흰 바탕에 빵 **1개만** 올려 찍을 때. 박스를 자동으로 잡습니다 |
   | 여러 개 — 박스 고르기·고정 | 여러 빵이 같이 있을 때. 새 빵을 골라 품목을 지정합니다 |
3. **수집 카메라 시작** → 화면에 **초록 박스**가 빵에 딱 맞게 보이는지 확인합니다.
   - 「NO BOX」 가 뜨면 저장되지 않습니다. 빵 1개만, 흰 바탕 위에 올려 주세요.
4. **목표 촬영 수** (보통 200장) → **자동 수집 시작**
   - 턴테이블이 있으면 「촬영 중 턴테이블 자동 회전」 을 켜 두세요. 돌려가며 찍습니다.
   - 없으면 촬영 중에 빵을 조금씩 돌리거나 옮겨 주세요.
5. 다 찍으면 **학습용 ZIP으로 내보내기** → 젯슨으로 자동 전송됩니다.

## 6. 라벨링 프로그램 사용법

사진에 **"여기에 무슨 빵이 있다"는 박스(라벨)** 를 붙이는 프로그램입니다.
**젯슨 AI가 먼저 박스를 쳐 주고, 사람은 틀린 것만 고칩니다.**
저장 형식은 **LabelImg YOLO 형식**과 같아서 LabelImg 로 열거나 Colab 학습에 그대로 쓸 수 있습니다.

### 6-1. 켜기
- PC: 폴더에서 **`run_autolabel.bat` 더블클릭**
- 젯슨에서 직접: `python3 autolabel.py`

창 맨 위를 확인합니다.

| 표시 | 뜻 | 할 일 |
|---|---|---|
| 🟡 젯슨 찾는 중… | 찾는 중 | 5초쯤 기다리기 |
| 🟢 http://…:8092 · 12클래스 | **연결됨** | 시작! |
| 🔴 젯슨 연결 안 됨 | 못 찾음 | **🔌 젯슨 주소** 버튼 → 젯슨 IP 입력 (예: `192.168.0.23`) |

### 6-2. 사진 폴더 준비
```
📁 빵사진_0911
   ├ classes.txt     ← (있으면 좋음) 빵 이름 12줄. 없으면 자동으로 만듭니다
   ├ 사진1.jpg
   └ 사진2.jpg …
```

### 6-3. 자동 라벨링
1. **📂 폴더 열기** → 사진 폴더 선택
2. **🤖 자동 라벨링** → 막대가 다 찰 때까지 기다리기 (100장에 약 1분)
3. 끝나면 모든 사진에 박스가 붙어 있습니다.

| 옵션 | 설명 |
|---|---|
| 저장 기준 0.30 | 이보다 자신 없는 박스는 만들지 않음 |
| 좌우반전 보강 | 사진을 뒤집어 한 번 더 봄 (놓침 감소, 2배 느림) |
| 미검수 자동 라벨도 다시 | 아직 확인 안 한 자동 라벨도 새로 만듦 (확인 완료한 것은 안 건드림) |

### 6-4. 검사하고 고치기 ⭐ 가장 중요
사진을 한 장씩 보며 **"박스가 빵에 딱 맞고 이름도 맞나?"** 만 봅니다.

**왼쪽 사진 목록의 표시**

| 표시 | 뜻 |
|---|---|
| ○ 회색 | 라벨 없음 |
| ● 파랑 | 자동 라벨 (아직 확인 안 함) |
| ⚠ 주황 | **확인 필요** (자신 없는 박스가 있거나 아무것도 못 찾음) |
| ✔ 초록 | 확인 완료 |
| ■ 보라 | 원래 있던 라벨 (직접 만든 것) |

왼쪽 위 목록을 **「⚠ 확인 필요」** 로 바꾸면 헷갈린 사진만 모아 볼 수 있습니다.

**다 맞으면** → `Space` (확인 완료 + 다음 사진)

**틀렸으면**

| 이런 경우 | 이렇게 |
|---|---|
| 빵 이름이 틀림 | 박스 클릭(빨갛게 됨) → 오른쪽 목록에서 맞는 이름 클릭 (또는 **숫자키**, 또는 박스 **우클릭**) |
| 박스 크기가 안 맞음 | 박스 클릭 → **모서리의 작은 네모**를 끌기 |
| 박스 위치가 어긋남 | 박스 **가운데를 잡고 끌기** |
| 빵이 있는데 박스가 없음 | `Esc` → 숫자키로 빵 이름 고르기 → **빈 곳에서 빵 왼쪽 위 → 오른쪽 아래로 끌기** |
| 빵이 아닌데 박스가 있음 | 박스 클릭 → `Delete` |
| 실수했음 | `Ctrl + Z` |

> ⚠️ **"틀린 박스"보다 "빠진 박스"가 더 위험합니다.** 빵이 있는데 박스가 없으면 AI가 "이건 빵이 아니다"라고 배웁니다.
> 사진마다 **빵 개수 = 박스 개수** 인지 꼭 세어 주세요. (⚠ 표시는 빠진 박스를 알려주지 못합니다)

사진을 넘기면 **자동 저장**됩니다.

### 6-5. 단축키

| 키 | 동작 | 키 | 동작 |
|---|---|---|---|
| `Space` | 확인 완료 → 다음 | `A` / `D` (←/→) | 이전 / 다음 사진 |
| `F` | 다음 미검수 사진 | `R` | 이 사진만 다시 자동 라벨 |
| `Delete` | 선택 박스 삭제 | `Esc` | 선택 해제 |
| `Ctrl + Z` | 되돌리기 | `Ctrl + S` | 저장 |

**숫자키 = 빵 이름** (박스를 선택한 상태면 그 박스 이름을 바꾸고, 선택이 없으면 새 박스 이름이 됩니다)

| 키 | 빵 | 키 | 빵 | 키 | 빵 |
|---|---|---|---|---|---|
| `1` | baggette 바게트 | `5` | salt 소금빵 | `9` | plain 플레인 |
| `2` | muffine 머핀 | `6` | pie 파이 | `0` | waffle 와플 |
| `3` | pizza 피자빵 | `7` | fruit 과일 | `-` | almond 아몬드 |
| `4` | moca 모카빵 | `8` | rotus 로투스 | `=` | maple 메이플 |


### 7-3. PC 에서 학습 버튼 누르기
**「모델 배포 및 모델 학습」 탭**

1. **기존 best.pt 선택** → `models/m13_A.pt` (기본값)
2. **분할** (「합성 데이터 만들기」 켠 채로)
   → 기본 12종 데이터 + 새로 찍은 사진을 합치고, 빵 1개 사진을 오려 여러 개 놓인 사진도 만듭니다.
3. **전이학습 시작** → 학습 → 엔진 변환 → 적용까지 자동으로 이어집니다.
   (젯슨 Orin Nano 에서 사진 약 1,700장 기준 epoch 당 2~3분. 급하면 epoch 을 8~15 로 줄이세요)

> 💡 **더 빨리 학습하기 — 앞쪽 층 고정(freeze):** `database/settings.json` 에 `"training_freeze": 10` 을 넣으면
> 이미 배운 특징 추출 층(0~9번)을 그대로 두고 뒤쪽만 학습합니다. 빨라지고 기존 빵을 덜 잊지만 새 빵에는 덜 맞춰질 수 있습니다.
> 기본은 0 (고정 안 함).

> ⚠️ 학습은 **한 번에 하나만** 돌리세요. 젯슨 메모리(8GB)에 학습 두 개가 겹치면 멈추고 재부팅됩니다.

> ⚠️ 학습 버튼으로 새 모델을 적용하면 **그 모델 하나로** 돌아갑니다 (앙상블 짝이 풀림).
> 앙상블로 되돌리는 방법은 [8-4](#8-4-모델앙상블-바꾸기) 를 보세요.

## 8. AI 모델과 앙상블 구성

### 8-1. 들어 있는 모델
`models/` 에 아래 4개 모델의 **엔진(.engine) · ONNX · pt · 클래스 목록(.names.json)** 이 모두 들어 있습니다. 전부 12종입니다.
원하는 모델을 골라 쓰거나, pt 로 이어서 학습할 수 있습니다.

| 모델 | 구조 | 학습 데이터 | 비고 |
|---|---|---|---|
| **`m13_A`** ⭐ | YOLO11n | bread_dataset_0914 (학습 1,629장) 원본 · 40 epoch | **기본 대표 모델** — 처음 보는 사진에서 단독 1위 |
| **`m13_B`** ⭐ | YOLO11n | 같은 데이터 + 90° 돌린 사본 · 회전 ±10° · 30 epoch | **기본 앙상블 짝** |
| `bread_0914` | YOLO11n | bread_dataset_0914 (Colab) | 이전 대표 모델 |
| `bread_0915_26n` | YOLO26n | bread_dataset_0914 (Colab) | 구조 비교용 |

`bread_0911` · `m12_A` · `m12_B` · `base.pt` 는 예전 구성입니다 (엔진 없이 ONNX/pt 만).

> ⚠️ 엔진은 **Jetson Orin Nano Super · JetPack 6.2 (L4T R36.5) · TensorRT 10.3** 에서 만든 것입니다.
> 기종이나 JetPack 버전이 다르면 열리지 않으니 `./jetson/build_engines.sh --force` 로 ONNX 에서 다시 만드세요.

### 8-2. 두 모델을 합치는 방법
```
사진 ─┬─ m13_A ─┐
      └─ m13_B ─┤
                ▼
  ① 소프트 보팅(WBF): 같은 자리·같은 빵이면 박스를 합치고, 두 모델이 동의하면 신뢰도를 올린다 (2표)
     한 모델만 찾은 빵도 남긴다 (놓침을 줄이기 위해)
  ② 같은 자리에 이름이 다르게 나오면 확신이 높은 쪽 하나만 남긴다
  ③ 「상품 인식 실행」 버튼은 사진을 좌우로 뒤집어 한 번 더 보고 합친다 (TTA)
```
- 모델마다 한 번씩 돌리므로 추론 시간은 단독의 약 2배입니다 (상품 인식 약 40ms → 80ms).
- 일부 빵만 배운 모델은 `<엔진>.scope.json` 으로 역할 분담도 됩니다 (예: `bread_0911.engine.scope.json`).

### 8-3. 성능 비교 (처음 보는 사진 124장)
학습에 쓰지 않은 테스트셋 `breadtest_0913` (124장 · 빵 1,056개), 12종 전체 기준입니다.

| 구성 | mAP50-95 | 오류 — 상품 인식 (TTA) | 오류 — 실시간 (TTA 끔) |
|---|---|---|---|
| **m13_A + m13_B (기본)** | 0.977 | **20** | 23 |
| bread_0914 + m13_B | 0.969 | 21 | 16 |
| m13_A 단독 | **0.982** | 23 | 21 |
| m13_B 단독 | 0.974 | 23 | 27 |
| bread_0914 단독 | 0.968 | 24 | 22 |
| bread_0914 + bread_0915_26n | 0.968 | 27 | 24 |
| bread_0915_26n 단독 | 0.971 | 33 | 78 |

- mAP50-95 는 TTA 켬 기준, 오류 = 착각 + 놓침 + 없는 빵 찾음 (신뢰도 0.45 기준).
- **앙상블 효과는 작습니다** (단독 대비 오류 3~4개 감소, 추론 시간 2배). 가볍게 쓰려면 `m13_A` 단독도 괜찮습니다.
- 휴대폰 앱 화면을 빵(주로 로투스)으로 착각하는 일이 있어, 「회원 QR 스캔」 중에는 빵 인식을 멈춥니다 ([회원 적립](#회원-적립-qr)).
- 다시 재려면: `python3 training/compare_ensemble.py --test <테스트셋 zip 또는 폴더>`
  → `runs/model_compare_ens/` 에 표(CSV)와 빵 그룹별 차트가 저장됩니다.

### 8-4. 모델·앙상블 바꾸기
`database/settings.json` 을 고치고 다시 켭니다. 단독으로 쓰려면 `"ensemble_engines": []`.
```json
{
  "active_engine": "models/m13_A.engine",
  "ensemble_engines": ["models/m13_B.engine"]
}
```
```bash
cd ~/breadvision
./jetson/build_engines.sh     # 새로 쓰는 모델의 엔진이 없으면 만든다
./jetson/start.sh
```
켜 둔 채로 바꾸기 (재시작 없이):
```bash
curl -X POST localhost:8092/deploy   -H 'Content-Type: application/json' -d '{"engine": "models/m13_A.engine"}'
curl -X POST localhost:8092/ensemble -H 'Content-Type: application/json' -d '{"engines": ["models/m13_B.engine"]}'
```
`/deploy` 는 앙상블 짝을 풀므로 짝은 그다음에 `/ensemble` 로 붙입니다. 둘 다 `settings.json` 에 저장돼 재부팅해도 유지됩니다.

## 9. 턴테이블 (선택)

새 빵을 돌려가며 자동으로 찍는 장치입니다. **STM32 Nucleo-F401RE + ULN2003 드라이버 + 28BYJ-48 모터**

### 9-1. 배선
| 연결 | Nucleo 핀 |
|---|---|
| 모터1 드라이버 IN1~IN4 | **D2, D3, D4, D5** |
| 모터1 버튼 (선택, 반대쪽 다리는 GND) | D6 = 왼쪽, D7 = 오른쪽 |
| 모터2 드라이버 IN1~IN4 (버튼 전용) | **D8, D9, D10, D11** |
| 모터2 버튼 (반대쪽 다리는 GND) | A0 = 왼쪽, A1 = 오른쪽 |
| 드라이버 전원 | 5V, GND |

D0·D1 은 USB 통신에 쓰이므로 **절대 연결하지 마세요.**

### 9-2. 펌웨어 올리기 (한 번)
PC 에서 VS Code + **PlatformIO** 확장을 설치하고 `turntable` 폴더를 연 뒤 **Upload(→ 버튼)** 를 누릅니다.
또는 명령어로 (Nucleo 를 USB 로 연결한 컴퓨터에서):
```bash

cd turntable
pio run -t upload
```

### 9-3. 사용
Nucleo 를 **젯슨 USB** 에 꽂으면 끝입니다. 젯슨이 자동으로 찾습니다.
PC 의 「데이터 수집」 탭에서 「촬영 중 턴테이블 자동 회전」 을 켜고 수집하면 됩니다.

## 13. 테스트와 로그

### 자동 테스트
카메라·GPU·젯슨·인터넷 없이 도는 테스트가 `tests/` 에 있습니다. GitHub 에 올리면 **Actions** 탭에서 자동으로 돌고, 커밋 옆에 초록 체크(통과) / 빨간 X(실패)가 뜹니다.

PC 에서 직접 돌리기 (PowerShell):
```powershell
py -3.11 -m pip install -r requirements-ci.txt
py -3.11 -m pytest
```

| 파일 | 확인하는 것 |
|---|---|
| `test_fuse.py` | 앙상블 결합 — 한 모델만 본 빵이 0.55 문턱 아래로 깎이지 않는지, 합의 보너스, 교차 억제 |
| `test_detector_postprocess.py` | TensorRT 출력 해석·letterbox 되돌리기·겹친 박스 제거 |
| `test_jetson_ops.py` | 젯슨 원격 작업의 안전장치 (프로젝트 밖 경로·확장자·작업 이름 거부) |
| `test_core_cart.py` | 주문 금액·수량 계산 |
| `test_collect_labeler.py` | 수집 탭 「여러 개」 방식의 지정·무시·고정 규칙 |
| `test_gui_smoke.py` | 가짜 카메라·추론기로 POS 창 전체를 띄워 인식 → 주문 → QR → 결제, 상품 등록, 수집을 눌러 봄 |

### 로그
POS 는 `사용자폴더\.breadvision\logs\pos.log` 에 기록합니다 (2MB 씩 3개까지). 오류가 나면 이 파일에 시각·위치·원인이 남습니다.
젯슨 추론 서버는 전처럼 `~/.breadvision/logs/infer.log` 입니다. 자세한 로그가 필요하면 `BREADVISION_DEBUG=1` 로 켜세요.

**git 에 들어가지 않는 것** (`.gitignore`): 기본 4개 모델 외의 TensorRT 엔진(젯슨마다 새로 만듦), 데이터셋·학습 결과, 현장 설정(`database/settings.json`, `products.json`, `jetson.json`)
